# 학교 산업안전보건 통합 업무지원 시스템

스마트일정관리의 메인 화면을 기준으로 다음 5개 프로그램을 하나의 로컬 웹 프로그램으로 통합한 저장소입니다.

1. 스마트 일정·업무관리
2. AI 업무지원 챗봇
3. 산업안전보건 대표서식 자동화 19종
4. 시설안전 점검이력
5. MSDS·유해물질 관리

기존 `Form-Automation` 프로그램은 기능과 소스를 보존하여 `modules/forms`에 포함했습니다.

## 바로 실행하기

Windows와 Node.js 20.9 이상이 필요합니다.

1. 저장소를 ZIP으로 내려받아 압축을 풉니다.
2. 루트의 `실행하기.bat`를 더블클릭합니다.
3. 검은 실행 창을 유지한 채 브라우저에서 사용합니다.
4. 종료할 때 `종료하기.bat`를 실행합니다.

통합 메인 주소: `http://127.0.0.1:8080/shell/app.html`

### AI·법령 API 설정

필요할 때 [`.env.example`](./.env.example)을 `.env.local`로 복사하고 `OPENROUTER_API_KEY`와 `LAW_API_OC`를 입력한 뒤 프로그램을 재시작합니다. `.env.local`은 Git에서 제외되며, 키를 화면이나 채팅창에 입력할 필요가 없습니다. 키가 없는 동안 내장 검색과 규칙 기반 작성 기능은 계속 사용할 수 있습니다. 현재 로컬 저장 단계에서는 Supabase 키가 필요하지 않습니다.

서버는 OpenRouter 모델을 기능별로 고정합니다: 일정·챗봇 `openai/gpt-6-luna`, MSDS `google/gemini-3.1-flash-lite`, 서식 문안 정리 `openai/gpt-6-luna`. `http://127.0.0.1:8080/api/ai/status`와 `/api/law/status`에서 키 설정 여부만 확인할 수 있으며 키 값은 반환하지 않습니다. AI 사용을 선택하면 요청 내용이 외부 모델 제공자에게 전송됩니다. 서버는 주민번호·연락처 등 일부 개인정보 패턴을 가리지만, 전송 전 이름·건강정보를 직접 제거해야 합니다. 생성 결과는 저장·반영 전에 검토해야 합니다.

상세 사용법은 [README_실행방법.md](./README_실행방법.md), 변경 및 검증 범위는 [reports](./reports) 폴더를 참고하세요.

## 주요 구조

```text
shell/                  스마트일정 기반 통합 화면
modules/forms/          대표서식 자동화
modules/facility/       시설안전 점검이력
modules/chatbot/        AI 업무지원 챗봇
modules/msds/           MSDS·유해물질 관리
launcher/               시작·종료·상태 점검
reports/                분석·통합·테스트 보고서
```

## 데이터와 보안

- 서버는 `127.0.0.1`에만 열립니다.
- 화면에 필요한 정적 파일만 제공하며 `.env.local`, 실행 로그, 서버 소스, MSDS 임시 업로드 경로는 HTTP 접근을 차단합니다.
- API 키와 실제 업무 데이터는 저장소에 포함하지 않았습니다.
- 실행 로그와 PID는 `runtime`에 생성되며 Git에서 제외됩니다.
- 서로 다른 프로그램의 로컬 데이터를 자동 병합하거나 삭제하지 않습니다.
- 법령·AI 외부 연결은 로컬 서버를 통해 사용하며 인증키는 `.env.local` 또는 서버 환경변수에서만 읽습니다.

## 검증 상태

- 네 로컬 서비스 기동 및 HTTP 상태 확인 완료
- 대표서식 자동 테스트 17/17 통과
