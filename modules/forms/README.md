# 산업안전보건 서식 자동화

학교·기관의 산업안전보건 서식을 작성하고, 전자서명과 문서 보관, 인쇄를 처리하는 로컬 웹 프로그램입니다.

## 실행

1. 이 폴더의 **`실행하기.bat`**을 더블클릭합니다.
2. 최신 화면을 준비한 뒤 기본 브라우저에서 **http://localhost:5173/**을 자동으로 엽니다.
3. 기본 정보를 설정하고 필요한 서식을 선택해 작성합니다.

Node.js 18 이상과 npm이 필요합니다. 이 컴퓨터에 구성 요소가 이미 설치되어 있으면 인터넷 없이 실행할 수 있습니다. 구성 요소가 없는 경우에는 최초 실행 시 인터넷으로 설치합니다.

폴더 이름에 한글이나 공백이 있어도 실행할 수 있으며, 바로가기를 통해 실행해도 프로그램이 있는 폴더를 기준으로 작동합니다. 실행할 때마다 소스를 다시 빌드하므로 수정한 내용이 반영됩니다.

서버는 이 컴퓨터에서만 접근할 수 있도록 실행됩니다. 브라우저를 닫아도 서버는 백그라운드에 남으며, 다시 더블클릭하면 같은 서버를 사용합니다. Windows를 종료하거나 다시 시작하면 서버도 종료됩니다.

## 작성 시기별 서식 선택

기존 화면 디자인을 복원하고, 상단의 ‘서식명’을 작성 시기별로 분류했습니다.

- **매월:** 정기점검 실시 결과 보고, 안전보건협의체 회의록
- **분기별:** 합동점검표 (04-01-08)
- **교육 실시 시:** 안전보건교육일지, 근골격계 교육일지, MSDS 교육일지
- **재해 발생 시:** 산업재해조사표, 중대재해 발생보고, 재발방지 계획서
- 나머지는 보호구 지급, 공사·용역 준비 및 작업, 위험성평가·개선, 근골격계 조사·개선 시점으로 분류했습니다.

이번에 정리한 목록에 연간 작성 대상 서식이 없어 ‘매년’ 분류는 추가하지 않았습니다. 기존 위험성평가 예시 서식은 ‘위험성평가 실시·개선 시’에서 계속 선택할 수 있습니다. 선택란에 마우스를 올리면 해당 서식의 작성 시기 안내를 볼 수 있습니다.

04-01-08의 두 항목은 같은 원래 서식 번호를 사용하며 회의록·합동점검 종류를 함께 저장합니다. 기존 저장 자료도 그대로 열 수 있습니다.

## 결재용 본문 만들기

1. 서식의 기간·담당자·점검 결과 등을 입력한 뒤 점검표 오른쪽의 **결재용 본문 만들기**를 누릅니다. 화면이 좁으면 점검표 위에 표시됩니다. 저장하기 전 입력 내용도 반영됩니다.
2. 해당 서식에 맞는 보고 문장과 번호 항목이 생성됩니다. 정기점검은 주차별 날짜에서 대상 월과 점검기간을, 회의록·합동점검표는 입력한 월·분기를 반영합니다. 교육·재해·조사·평가 서식도 각 서식의 입력 항목을 사용합니다.
3. 본문에서 관련 근거와 `[입력 필요]` 등 대괄호로 표시된 빈 항목을 보완하고 문장을 수정합니다. **본문 복사**를 누른 뒤 내부 결재 시스템에 붙여넣습니다.

서식에 없는 관련 문서번호나 법령 근거, 미입력 결과는 임의로 생성하지 않습니다. 화면에만 표시되는 예시 행도 자동으로 완료 사실로 보고하지 않습니다. 인터넷이나 AI 서비스 연결 없이 로컬에서 생성합니다.

모달에서 수정한 본문은 원래 서식과 별개이며, 닫으면 보관되지 않습니다. 복사 기능을 사용할 수 없는 브라우저에서는 **전체 선택** 후 `Ctrl+C`로 복사할 수 있습니다. 보관함 문서는 먼저 불러와서 본문을 생성합니다.

## 문서 보관

- 기본 정보와 저장한 문서는 **현재 브라우저 프로필의 로컬 저장소(localStorage)**에 보관됩니다.
- 기존 문서는 같은 브라우저·프로필에서 `http://localhost:5173/`로 접속해야 보입니다. `127.0.0.1` 주소, 다른 포트, 다른 브라우저에서는 별도 저장소가 사용됩니다.
- 브라우저의 사이트 데이터를 삭제하거나 시크릿 모드를 종료하면 보관한 자료가 사라질 수 있습니다. 중요한 문서는 PDF 등 별도 파일로도 저장해 주세요.
- 프로그램 폴더를 복사하는 것만으로 브라우저에 보관한 문서가 함께 백업되지는 않습니다.
- 선택 기능인 Supabase 연동과 Gemini AI 요약에는 별도 설정과 인터넷 연결이 필요합니다. DB 연동 설정은 상단 ‘설정된 기본 기관’ 옆의 작은 **DB 연동** 버튼에서 열 수 있습니다. 설정하지 않으면 기본 로컬 작성·보관 기능을 사용할 수 있습니다.

## 실행 문제가 있는 경우

- **Node.js를 찾을 수 없음:** Node.js LTS를 설치하고 실행 창을 다시 엽니다.
- **5173번 포트 사용 중:** 이전 개발 서버나 다른 폴더에서 실행한 서버를 종료한 뒤 다시 실행합니다. 문서 저장소의 주소를 유지하기 위해 다른 포트로 자동 전환하지 않습니다.
- **빌드 실패:** 실행 창에 표시된 오류를 확인합니다. 오류가 나면 창이 닫히지 않습니다.
- **서버 시작 실패:** `.runtime/server-error.log`를 확인합니다. 서버 실행 기록은 `.runtime/server.log`에 남습니다.

## 개발

```powershell
npm run dev
```

개발 서버 주소도 `http://localhost:5173/`입니다. 일반 실행 서버와 개발 서버를 동시에 실행할 수는 없습니다. 개발 서버를 사용하려면 기존 서버를 먼저 종료하세요.

```powershell
npm run build
```

배포용 화면은 `dist` 폴더에 생성됩니다. 일반 실행은 `scripts/launch.ps1`에서 빌드 후 `scripts/local-server.mjs`로 이 화면을 제공합니다.

결재용 본문 생성 검증은 `node --test tests/approval-body.test.mjs`로 실행합니다.
