### 기능 중복과 보존 원칙

스마트일정관리에도 간단한 서식·시설·MSDS 기록 화면과 로컬 업무원장 챗봇이 이미 들어 있습니다. 이는 다른 네 프로그램의 축소판에 가깝지만 기존 기능이므로 제거하지 않습니다.

- 각 메뉴의 기본 탭은 해당 전문 프로그램으로 연결합니다.
- 스마트일정관리의 기존 기능은 `기존 간편기록` 또는 `업무원장 안내` 보조 탭으로 유지합니다.
- 전문 프로그램의 데이터와 간편기록 데이터를 자동 병합하지 않습니다.
- 필요할 때만 제목·기한·상태 같은 최소 메타데이터를 일정 업무로 보내도록 선택형 연계를 둡니다.

## 3. 스마트일정관리 메인 화면 분석

실제 화면을 로컬 분석 서버에서 렌더링하여 메뉴 이동과 콘솔을 확인했습니다.

- 상단: 흰색 헤더, 프로그램명과 보조 정보
- 좌측: 약 233px의 짙은 남색 사이드바, 선택 메뉴는 밝은 파란색으로 표시
- 본문: 옅은 하늘색 배경, 둥근 흰색 카드, `Noto Sans KR`/맑은 고딕 계열 글꼴
- 홈 배치: 오늘의 안전업무 캘린더, 지연·임박·오늘·이번 주 요약, 빠른 등록, 로컬 챗봇, 최근 서식·시설·MSDS 기록
- 기존 메뉴: 홈, 일정·업무관리, AI 업무지원 챗봇, 대표서식 자동화, 시설안전 점검이력, MSDS 업무지원, 설정
- 메뉴 전환: 동일 URL에서 화면을 교체하는 SPA 방식이며 전체 페이지 새로고침이 발생하지 않음
- 반응형: 약 1500px와 820px 전후의 레이아웃 조정 규칙 존재

따라서 새 디자인을 별도로 만들기보다 현재 화면을 그대로 통합 셸로 발전시키는 것이 요구사항과 가장 잘 맞습니다.

## 4. 검토한 통합 방식

| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 모든 코드를 한 문서로 직접 병합 | 하나의 DOM과 런타임 | CSS/ID/전역 함수/라이브러리 충돌, 향후 개별 수정 어려움, 회귀 위험 큼 | 제외 |
| 링크 또는 새 탭 연결 | 구현이 단순하고 격리됨 | 하나의 프로그램처럼 느껴지지 않고 화면·상태가 분리됨 | 제외 |
| 전부 같은 출처로 재작성/프록시 | URL과 배포가 단순 | 기존 localStorage/IndexedDB 출처가 바뀌어 데이터가 자동으로 보이지 않음, 변경 범위 큼 | 1차 통합에서는 제외 |
| 영구 유지 iframe + Shadow DOM + 통합 실행기 | 기존 런타임·데이터 출처 보존, 충돌 격리, 메뉴 전환 시 상태 유지, 향후 교체 용이 | 여러 로컬 서비스의 시작/상태 관리 필요 | **채택** |

## 5. 제안 통합 아키텍처

### 5.1 전체 구성

스마트일정관리 화면을 `통합 셸`로 사용하고, 기능 화면은 최초 접근 때 한 번만 생성한 뒤 숨김/표시로 전환합니다. 현재 스마트 앱처럼 `innerHTML`을 매번 교체하면 iframe과 작성 중 상태가 사라질 수 있으므로 모듈 호스트를 영구 유지합니다.

| 영역 | 통합 방식 | 예정 주소/출처 | 이유 |
|---|---|---|---|
| 통합 셸·스마트 일정 | 기존 UI를 기반으로 직접 포함 | `http://127.0.0.1:8080` | 메인 화면 및 공통 메뉴 |
| 대표서식 | 영구 유지 iframe | `http://localhost:5173` | React/CSS/전역 격리, 기존 저장소 출처 유지 |
| 시설안전 | Shadow DOM 직접 마운트 | 셸 출처 내부 | 원본이 공식 마운트 API와 CSS 격리를 제공 |
| 챗봇 | 영구 유지 iframe, 임베드 모드 | `http://127.0.0.1:3001` | Next 런타임 격리, 3000 충돌 제거. 셸 출처만 프레임 허용 |
| MSDS | 영구 유지 iframe | `http://localhost:3000` | 서버/Python/업로드 경로와 기존 저장소 출처 유지 |

`실행하기.bat` 하나가 필요한 서비스를 시작하고 상태를 점검한 뒤 통합 메인 주소만 엽니다. 종료 시 사용할 `종료하기.bat`도 제공하여 백그라운드 프로세스를 안전하게 정리하도록 합니다.

### 5.3 프로그램 간 연계

기본은 독립 모듈이며, 연계는 사용자가 선택할 때만 수행합니다.

- 서식 저장 완료 → 선택 시 일정 업무 생성
- 시설 지적사항·재점검 기한 → 선택 시 후속 업무 생성
- MSDS 정기 검토일 → 선택 시 일정 업무 생성
- 챗봇의 관련 작업 버튼 → 해당 전문 모듈 메뉴 열기
- 학교명 등 공통 기본정보 → 설정에서 명시적으로 복사

iframe 연계는 엄격한 출처 목록을 적용한 `postMessage` 브리지로 처리하고, 레코드 ID·제목·날짜·상태만 전달합니다. API 키, 전체 문서, 개인정보는 전달하지 않습니다.

## 6. 데이터 보존 및 보안 설계

1. 원본 ZIP과 원본 폴더는 읽기만 하며 결과 폴더에 복사본을 구성합니다.
2. 기존 localStorage/IndexedDB 키는 이름을 바꾸거나 삭제하지 않습니다.
3. 기존 출처를 유지할 수 있는 서식과 MSDS는 원래 포트를 유지합니다.
4. 스마트일정과 시설안전은 출처 변경 가능성이 있으므로 통합 전 백업 파일을 만들고 명시적 가져오기를 제공합니다.
5. 같은 이름의 데이터를 자동 병합하지 않고, 미리보기와 중복 검사를 거친 사용자 선택형 가져오기를 사용합니다.
6. API 키는 보고서·로그·브리지에 출력하지 않습니다. 기존 평문 키는 자동 이전하지 않으며, 서버측 환경변수 사용이 가능한 챗봇은 그 방식을 유지합니다.
7. MSDS 서버는 `127.0.0.1`에만 바인딩하고 CORS를 통합 셸 출처로 제한합니다. 요청/파일 크기 제한과 업로드 보존·삭제 정책을 추가합니다.
8. QRCode와 SheetJS는 정확한 버전을 프로젝트 내부에 포함해 인터넷 없이도 실행되도록 하고 라이선스 고지를 보존합니다.
9. Supabase 동기화는 기본 비활성 상태로 두고 사용자가 명시적으로 구성한 경우에만 사용합니다.

개발용 `.git`, `.backups`, 전체 `node_modules`는 그대로 복제하지 않고 필요한 원본 소스와 빌드 산출물만 포함합니다. 라이선스와 의존성 잠금 파일은 유지합니다.

## 8. 확인된 문제와 해결 계획

| 문제 | 영향 | 해결 계획 |
|---|---|---|
| 챗봇과 MSDS가 모두 3000 포트 사용 | 동시 실행 불가 | MSDS는 기존 3000 유지, 저장 데이터가 없는 챗봇을 3001로 이동 |
| 챗봇의 프레임 차단 헤더 | 통합 화면 내 표시 불가 | `DENY`를 제거하고 셸의 정확한 출처만 허용하는 CSP 적용 |
| 스마트 앱 렌더가 화면 DOM을 교체 | 메뉴 이동 시 iframe/작성 상태 소멸 가능 | 모듈 호스트를 한 번 생성하고 show/hide 방식으로 전환 |
| MSDS 외부 CDN 의존 | QR·엑셀 기능이 오프라인에서 실패 | QRCode/SheetJS를 로컬 자산으로 고정 |
| 현재 PC에 Python 없음 | PDF/HWP/HWPX/XLSX 고급 파서 실행 불가 | 승인 후 Python 3.11+ 실행환경 또는 휴대형 런타임을 구성하고 검증 |
| `requirements.txt`에 `openpyxl` 누락 | XLSX 파서 실패 | 실제 import 기준으로 의존성 명세 보완 |
| 출처별 웹 저장소 | HTTP 전환 시 과거 파일 실행 데이터가 자동으로 안 보임 | 모듈별 JSON 내보내기/가져오기, 사전 백업, 중복 미리보기 |
| API 키 평문 localStorage | 로컬 사용자에게 노출 가능 | 자동 이동 금지, 민감값 로그 제외, 가능한 키는 서버 환경변수 사용 |
| MSDS 서버의 광범위한 네트워크 허용 | 같은 네트워크에서 접근될 수 있음 | loopback 바인딩, 제한 CORS, 입력 크기·파일 검증 |
| 서식 앱 큰 번들 | 첫 화면 로딩 지연 가능 | 코드 분할 검토. 기능 안정성을 우선해 무리한 재작성은 하지 않음 |

## 9. 현재까지의 검증 결과

### 정상 확인

- 스마트일정관리: 실제 렌더링, 기존 7개 메뉴 전환, URL 유지(전체 새로고침 없음), 홈/서식/시설/MSDS 간편 화면 표시, 브라우저 콘솔 오류 없음
- 대표서식: `npm run build` 성공, 기존 자동 테스트 17건 모두 통과, 19개 서식 템플릿 존재 확인
- 시설안전: 실제 렌더링, 5개 메뉴와 대시보드 표시, 콘솔 오류 없음
- MSDS: 초기 화면 실제 렌더링, 콘솔 오류 없음

### 확인된 오류/제약

- 대표서식 빌드에서 약 650KB JavaScript 청크 크기 경고
- MSDS 화면에서 외부 CDN의 QRCode/SheetJS 객체가 로드되지 않음
- 현재 PC에 Python이 없어 MSDS 서버측 문서 파서를 실행할 수 없음
- 챗봇은 의존성이 압축에 포함되지 않았고 현재 프레임 차단 설정이 있어 런타임 검증 전 수정/설치 필요

### 아직 미검증

- 제공된 실제 업무 문서를 사용한 스마트 PDF OCR 정확도
- 19개 서식 각각의 브라우저 인쇄/PDF/HWP 호환 결과
- 시설안전 실제 PDF 평가표 파싱·사진 첨부·누적 이력·결과보고
- OpenAI 키가 있는 경우의 챗봇 온라인 응답(키 없는 로컬 검색 모드는 구현 확인)
- MSDS 사진 인식, 외부 공공데이터, 실제 PDF/HWP/HWPX/XLSX 파싱, Excel/PDF/라벨/QR 출력
- 새로고침·브라우저 재시작 뒤 각 모듈의 전체 데이터 복원
- 모바일·태블릿 실기기 레이아웃

미검증 항목은 통합 개발 후 실제 샘플과 필요한 실행환경을 갖춰 별도로 판정하며, 정상으로 간주하지 않습니다.
