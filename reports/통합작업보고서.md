# 5개 프로그램 통합 작업 보고서

작성일: 2026-10-22  
결과물: `통합업무프로그램`

## 1. 완료 결과

스마트일정관리의 기존 화면을 통합 셸로 사용하고, AI 챗봇·대표서식·시설안전·MSDS 전문 프로그램을 같은 사이드 메뉴에서 전환할 수 있도록 통합했습니다. 기존 스마트 기능은 그대로 유지했으며 전문 화면과 중복되는 기능도 `기존 간편기록` 보조 탭에서 사용할 수 있습니다.

원본 ZIP 5개와 원본 다운로드 폴더는 수정하거나 삭제하지 않았습니다. 작업은 별도 복사본에서 수행했고 완성본만 새 결과 폴더로 패키징합니다.

## 2. 채택한 구조

| 구성 | 방식 | 포트/저장소 |
|---|---|---|
| 통합 셸·스마트 일정 | 기존 HTML/CSS/JS 직접 사용 | 8080 / 기존 `appData` 키 |
| 대표서식 | 영구 iframe, Vite 정적 빌드 | 5173 / 기존 localStorage |
| 시설안전 | Shadow DOM 직접 마운트 | 8080 출처 / IndexedDB `school-safety-history-v1` |
| 챗봇 | 영구 iframe, Next.js standalone | 3001 / 대화 메모리 |
| MSDS | 영구 iframe, Node 서버 | 3000 / 기존 localStorage 및 `uploads` |

모든 코드를 한 DOM으로 합치면 전역 변수·스타일·ID·라이브러리 충돌과 회귀 위험이 큽니다. 따라서 각 프로그램의 기술 구조를 유지하면서 통합 셸만 화면 전환을 관리하는 방식을 사용했습니다.

## 3. 주요 변경 사항

### 통합 셸

- 기존 스마트일정관리의 디자인, 메뉴 순서, 홈 캘린더와 카드 배치를 유지
- 전문 모듈용 영구 호스트와 연결 상태 표시 추가
- 메뉴 클릭을 가로채 동일 문서 안에서 모듈 전환
- 전문/기존 간편기록 탭과 새 창 열기 제공
- 데스크톱 우선 레이아웃과 기존 반응형 규칙에 맞춘 통합 CSS 추가

### 대표서식

- 원본 React/Vite 소스와 19개 서식 기능을 보존
- 검증된 `dist`를 실행 패키지에 포함해 별도 설치 없이 정적 실행
- iframe으로 CSS·전역 객체·요소 ID 충돌 방지

### 시설안전

- 원본이 제공하는 `SchoolSafetyHistory.mount()` API 사용
- Shadow DOM 내부의 원본 UI와 IndexedDB 방식을 그대로 유지
- 독립 실행용 `modules/facility/index.html` 추가

### 챗봇

- Next.js `output: standalone` 운영 빌드 생성
- MSDS와 겹치던 3000 포트를 3001로 분리
- `frame-ancestors 'none'`/`X-Frame-Options: DENY` 대신 통합 셸 출처만 허용
- `?embed=1`에서 중복 사이드바를 숨기는 임베드 화면 추가
- API 키가 없어도 내장 자료 검색 답변이 동작하도록 기존 폴백 유지

### MSDS

- 서버를 `127.0.0.1`에만 바인딩하고 통합 셸/자체 출처만 CORS 허용
- 요청 크기를 30MiB로 제한하고 정적 파일 경로 이탈 방지
- QRCode 1.0.0, SheetJS 0.18.5, PDF.js 3.11.174를 로컬 자산으로 고정
- `requirements.txt`에 실제 사용되는 `openpyxl` 명시
- 통합 실행 중 자동 브라우저 중복 실행 방지
- 구식 URL 파서를 WHATWG `URL`로 교체

### 실행·운영

- 한 번에 네 로컬 서비스를 준비하는 `launcher/start.mjs`
- 통합 실행기가 만든 프로세스만 종료하는 `launcher/stop.mjs`
- 네 서비스의 HTTP 상태를 확인하는 `launcher/healthcheck.mjs`
- 비전문가용 `실행하기.bat`, `종료하기.bat`, `상태확인.bat`
- 런타임 로그와 PID 정보를 결과 폴더의 `runtime`에만 저장

## 4. 충돌 해결 결과

| 충돌 가능성 | 해결 |
|---|---|
| JavaScript 전역 변수·함수명 | 전문 앱을 iframe, 시설 앱을 Shadow DOM으로 격리 |
| CSS/HTML ID | iframe 출처 분리 및 Shadow DOM 캡슐화 |
| 챗봇/MSDS 3000 포트 | 챗봇 3001, MSDS 3000으로 분리 |
| localStorage 키 | 기존 키를 변경하지 않고 출처별 저장소 유지 |
| 메뉴 전환 시 화면 초기화 | 모듈을 한 번 만든 뒤 숨김/표시 |
| 외부 CDN 실패 | MSDS 주요 라이브러리를 로컬 파일로 포함 |
| 프레임 보안 헤더 | 8080 통합 셸만 허용하도록 제한 |
| 서버의 외부 네트워크 노출 | 모든 신규 서비스는 loopback 주소로만 바인딩 |

## 5. 데이터 보존 결정

기존 저장 구조를 자동 변환하지 않았습니다. 웹 저장소는 실행 주소가 다르면 자동으로 공유되지 않기 때문에 스마트일정/시설안전의 과거 데이터를 이전할 때는 각 프로그램의 백업·내보내기와 복원·가져오기를 사용해야 합니다. 대표서식과 MSDS는 기존 포트를 유지해 같은 브라우저의 저장소를 계속 사용할 가능성을 높였습니다.

중복 자료를 자동 합치거나 덮어쓰는 기능은 데이터 손실 위험 때문에 제외했습니다. 공통 메타데이터 연계용 메시지 채널은 허용 출처와 메뉴명만 받도록 최소화했으며, 실제 업무 데이터 전송은 하지 않습니다.

## 6. 유지보수 구조

```text
통합업무프로그램/
├─ 실행하기.bat / 종료하기.bat / 상태확인.bat
├─ shell/                 # 스마트일정 기반 통합 화면
├─ modules/forms/         # 대표서식 소스와 실행 빌드
├─ modules/facility/      # Shadow DOM 시설 모듈
├─ modules/chatbot/       # 챗봇 소스와 standalone 실행 빌드
├─ modules/msds/          # MSDS 앱·서버·파서·로컬 라이브러리
├─ launcher/              # 시작·종료·상태 확인
├─ vendor/                # 공통 제3자 라이브러리와 고지
├─ runtime/               # 실행 중 생성되는 로그/PID
└─ reports/               # 분석·비교·작업·테스트 보고서
```

모듈별 원본 기술 구조를 유지했기 때문에 한 프로그램의 기능 추가가 다른 프로그램의 런타임과 스타일에 직접 영향을 주지 않습니다.

## 7. 남은 제약과 권고

- 현재 PC에 Python이 없어 MSDS 실제 PDF/HWP/HWPX/XLSX 서버 파서는 미검증입니다.
- 실제 업무문서를 사용한 19종 전체 인쇄/PDF/HWP 호환 결과와 시설 PDF 파싱 정확도는 별도 수용시험이 필요합니다.
- 스마트일정과 시설안전의 과거 `file://` 저장 데이터는 브라우저 보안상 자동 이동되지 않을 수 있으므로 백업 후 가져와야 합니다.
- 선택형 외부 AI·Supabase 기능은 사용자가 키를 구성하면 외부 전송이 발생할 수 있으므로 기관 정책을 먼저 확인해야 합니다.
- 장기 배포 전에는 기관 표준 PC 한 대에서 실제 샘플 문서와 프린터로 최종 수용시험을 권장합니다.
