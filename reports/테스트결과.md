시험일: 2026-10-22  
환경: Windows, Node.js v24.21.0, npm 11.19.0, 인앱 Chromium 브라우저  
판정: **통합 기본 기능 정상 / MSDS Python 고급 파서와 실제 문서 출력은 미검증**

## 2. 발견 후 수정한 사항

| 발견 내용 | 조치 | 재시험 |
|---|---|---|
| 원본 챗봇과 MSDS가 모두 3000 포트 사용 | 챗봇을 3001로 이동 | 네 서비스 동시 HTTP 200 |
| 챗봇 프레임 차단 | 통합 셸 출처만 CSP 허용 | 통합 메뉴 안에서 실제 화면 표시 |
| 스마트 스크립트의 렉시컬 `render`와 통합 렌더러 충돌 | 기존 렌더 함수를 보존하고 메뉴 캡처 단계에서 통합 화면 전환 | 전문 메뉴 4개 모두 정상 표시 |
| MSDS QR/Excel/PDF 외부 CDN 의존 | 버전 고정 로컬 자산으로 교체 | 4개 자산 HTTP 200 |
| MSDS 구식 `url.parse()` 경고 | WHATWG `URL`로 교체 | 재시작 후 경고 미발생 |
| MSDS `requirements.txt`의 `openpyxl` 누락 | 의존성 추가 | 명세 확인, 실행은 Python 부재로 미검증 |
| Windows CMD가 UTF-8 한글이 든 조건 블록을 구문 오류로 처리 | 실행 배치의 조건 흐름을 괄호 없는 ASCII 문장으로 변경 | 최종 폴더에서 `cmd.exe /c 실행하기.bat`로 네 서비스 정상 기동 |

## 3. 오류 및 제약

### 현재 확인된 치명적 오류

없음. 기본 실행과 다섯 프로그램의 첫 화면·메뉴 연결은 정상입니다.

### 비차단 제약

- 대표서식 운영 번들은 약 650KB JavaScript 청크 크기 경고가 있으나 빌드와 기능 테스트는 통과했습니다.
- 챗봇 대화는 원본 설계대로 새로고침하면 초기화됩니다.
- 통합 실행 전부터 5173 포트에 같은 대표서식이 실행 중이면 해당 서비스를 재사용합니다.

## 4. 미검증 항목

아래 항목은 정상으로 가정하지 않았습니다.

- 실제 업무 PDF를 사용한 스마트일정 OCR 정확도
- 19개 서식 각각의 실제 프린터 인쇄, PDF 저장, 한글 호환 HTML 열기
- 시설안전 실제 PDF 판정 매핑, 대용량 사진 리사이즈, 장기 누적 이력, 결과보고 출력
- OpenAI API 키를 설정한 챗봇 온라인 응답(키 없는 로컬 근거 검색만 검증)
- MSDS 실제 사진 인식, 외부 공공데이터 실서비스, 실제 MSDS PDF 파싱
- Python이 필요한 HWP/HWPX/XLSX/PDF 서버 파서
- MSDS 실제 QR 라벨 인쇄, Excel 다운로드 파일 내용, 교육자료 PDF/인쇄물 레이아웃
- 기존 운영 데이터의 백업→통합 복원 전체 수용시험
- 새 레코드 작성 후 브라우저 완전 종료·재실행까지 포함한 장기 저장 복원
- 브라우저 개발자 콘솔의 전체 로그 수집(화면상 오류와 서버 로그에는 오류 없음)
- 모바일·태블릿 실기기의 터치/회전/인쇄 동작

## 5. 권장 수용시험

기관에서 실제 사용할 대표 샘플을 개인정보 제거 후 준비하여 다음 순서로 확인하는 것을 권장합니다.

1. 기존 프로그램별 백업 파일 생성
2. 스마트일정 일정 1건 등록 후 새로고침·재실행 확인
3. 대표서식 19종에서 각 1건 저장하고 PDF/HWP 호환 결과 확인
4. 시설 PDF 1건과 전·후 사진을 등록해 완료 보고서 출력
5. MSDS 실제 PDF/HWPX/XLSX 각 1건을 Python 준비 PC에서 가져오기
6. 실제 프린터에서 라벨·1페이지 교육자료·결과보고 여백 확인
7. Chrome/Edge와 기관 표준 해상도에서 최종 승인
